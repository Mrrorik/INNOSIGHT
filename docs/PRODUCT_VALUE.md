# Продуктовая ценность

## Для кого

Команды, которые развивают GraphQL API: платформенные разработчики, QA, API owners и технические руководители. Особенно полезен контекст нескольких клиентских приложений, где использование схемы распределено между командами.

## Практическая проблема

Схема показывает, что API умеет. Наблюдаемые запросы показывают, что выбирают клиенты. Успешные assertions показывают, какие пути данных действительно проверяли. Эти три источника знаний часто живут отдельно.

INNOSIGHT связывает их через schema coordinates и версии. Команда получает список ненаблюдавшихся полей, неподтверждённые тестами зоны, deprecated usage, ошибки и операции, потенциально затрагиваемые изменением.

## Главное отличие от Playground

Playground выполняет запрос. INNOSIGHT сохраняет безопасный факт этого вызова, пересчитывает покрытие, отображает его на схеме, связывает с тестовым evidence и использует для оценки будущего изменения API.

Основной коммерческий сценарий — **Change Impact Intelligence**: перед удалением/изменением поля увидеть реальные операции, которые его выбирали, и связанные tests. Для enum/input changes учитываются типовые зависимости. Это консервативный анализ потенциального влияния; он не обещает знание всех клиентов или конкретных сохранённых значений аргументов.

## Измеримый результат

- Уменьшается количество полей без зарегистрированного тестового evidence после добавления проверок.
- Появляется воспроизводимый способ расследовать GraphQL errors внутри HTTP 200.
- API review получает конкретные observed consumers и тесты вместо предположений о неиспользуемом поле.
- Отчёт можно передать команде как JSON, CSV или печатный HTML.

Сами величины экономии времени и предотвращённых убытков текущая система не измеряет. ROI-калькулятор — иллюстративная модель с вводимыми пользователем параметрами.

## Возможная коммерческая модель

Self-hosted лицензия для команды или hosted subscription по числу проектов/объёму событий. Возможные платные уровни: длительная история, CI schema checks, SSO/RBAC, workspace policies и поддержка. Это идеи развития, а не уже работающие billing/enterprise features.

## Границы текущего продукта

Локальная демонстрационная платформа с реальным proxy, PostgreSQL, тестами, live UI и semantic diff. Не реализованы enterprise tenancy, SLA, billing, resolver tracing, distributed coordination, durable fail-open telemetry queue и масштабная SQL-предагрегация. Текущая автоматизация тестов запускает query; произвольные production mutations автоматически не генерируются и не выполняются.

Перед продажей production deployment потребуются нагрузочные испытания, политика данных, аутентификация, резервное копирование, retention и эксплуатационная модель. Техническая демонстрация уже позволяет проверить ключевую ценность на настоящем API.
